# هياكل البيانات المستخدمة فعلياً

PostgreSQL هو المصدر الرسمي. لا تحفظ الهياكل ملف المريض الطبي، ولا تمنح صلاحيات. جميع الهياكل في `backend/app/structures`، ويمكن اختبارها دون قاعدة بيانات أو واجهة.

## HashTable

تنفيذ FNV-1a على UTF-8 ثم باقي القسمة على عدد الحاويات. التصادمات عبر separate chaining بقوائم، وتوسعة هندسية عند حمل 0.75. لا يُستخدم dict لتخزين بنية الجدول.

Insert/Search/Delete متوسطها O(1)، وأسوأها O(n) عند التصادمات؛ إعادة التوسعة O(n) مع تكلفة إدخال مستهلكة amortized متوسطة O(1). الذاكرة O(n + capacity).

الربط الفعلي: `services/nfc.py` يفهرس SHA-256 للرمز إلى رقم سجل البطاقة، بحد أقصى 4096 مدخلة وقفل للخيوط. لا تُخزن الرموز الأصلية أو البيانات الطبية. كل hit يعيد التحقق من سجل PostgreSQL وactive؛ بذلك لا تصبح بطاقة ملغاة صالحة بسبب cache في عامل آخر. الإلغاء والاستبدال يبطلان المدخلة محلياً. إعادة تشغيل الخادم تبدأ cache فارغة. المقصود تقليل بحث hash الطويل إلى lookup بالمفتاح الأساسي، وليس الاستغناء عن قاعدة البيانات أو ادعاء سرعة غير مقاسة.

## Queue

قائمة مترابطة أحادية بعقد مستقلة ومؤشري head/tail. Enqueue/Dequeue/Peek/IsEmpty كلها O(1) في أسوأ حالة. الذاكرة O(n). لا list.pop(0) ولا deque.

الربط الفعلي: الحضور يحفظ checked_in_at؛ خدمة المواعيد تستعيد الصفوف حسب (checked_in_at, id)، وتضيفها إلى Queue. طلب المراجع التالي يستخدم dequeue ويغير الحالة إلى completed داخل معاملة. القفل الاستشاري PostgreSQL لكل مستشفى يمنع موظفين من أخذ الحالة نفسها. إعادة البناء O(n)؛ لا ندعي أن طلب API بكامله O(1). Queue مستخدمة أيضاً داخل BFS.

## PriorityQueue / Min-Heap

مصفوفة ثنائية مع عمليات bubble-up/down، وفهرس مواقع بواسطة HashTable اليدوي. المفتاح (priority, arrived_at, id). الرقم الأقل أعلى أولوية؛ التساوي بالأقدم ثم رقم السجل. المختص يحدد الأولوية، ولا تتخذ الخوارزمية قراراً طبياً.

Insert/ExtractMin/UpdatePriority متوسط O(log n) بسبب فهرس hash، وPeek O(1). أسوأ تصادمات hash تؤثر على حدود العمليات؛ لا ندعي ضماناً مطلقاً لفهرس hash. الذاكرة O(n). بناء heap عبر إدخالات متتالية O(n log n).

الربط الفعلي: خدمة الطوارئ تعيد بناء heap من PostgreSQL عند كل طلب، وتستخدم extract_min لعرض الترتيب وأخذ الحالة التالية، وupdate_priority عند تعديل حالة منتظرة. قفل المستشفى يحمي الاختيار المتزامن. استعادة الترتيب لا تعتمد على ذاكرة عملية سابقة.

## Graph

Adjacency List داخل HashTable اليدوي. الحواف موجهة: الاتصال A→B لا يعني B→A إلا بوجود حافة أخرى. BFS يستخدم Queue وHashTable visited/parent، ويعيد أقصر مسار بعدد الروابط. لا Dijkstra لأن الروابط غير موزونة.

BFS متوسط O(V+E)، والذاكرة O(V+E) للرسم وO(V) للبحث. إضافة node متوسط O(1)، وإضافة edge O(degree) لتجنب التكرار. أسوأ تصادمات HashTable قد تزيد التعقيد.

الربط الفعلي: المستشفيات Nodes وجدول hospital_connections هو مصدر Edges. إنشاء الإحالة يتأكد من وجود مسار، والواجهة تعرض المسار. الرسم لا يمنح مشاركة سجلات؛ هذه تخضع لمنح الوصول وshared وRBAC في API.

## الاختبارات والقياس

`python -m pytest tests/unit/test_structures.py -q`

`python -m scripts.benchmark --size 10000`

اختبارات عشوائية ثابتة البذرة تقارن hash/heap بنتائج مرجعية، مع تصادمات إجبارية، حذف، توسعة، تحديث أولوية، تعادل وصول، دورات graph وعقد غير متصلة. القياس يقارن البحث الخطي بالـHashTable داخل الذاكرة فقط، ويكتب النتائج الفعلية في benchmark_results.json. أمثلة الاستخدام العملية موجودة في الخدمات والاختبارات، وليست ملفات غير مستخدمة.
