# NFC: ESP8266/RC522 وESP32-S3/PN532 مع MIFARE Classic 1K

## خريطة الملفات

- `nfc_esp8266/src/main.cpp`: برنامج ESP8266/RC522.
- `arduino_ide/MediLink_RC522/MediLink_RC522.ino`: نسخة Arduino IDE للوحة ESP8266/RC522.
- `nfc_esp8266/platformio.ini`: نوع اللوحة ومكتبة MFRC522 وسرعة الاتصال ومنفذ الرفع.
- `nfc_esp32s3_pn532/src/main.cpp`: برنامج ESP32-S3/PN532، ويستخدم بروتوكول Serial وتنسيق البطاقة نفسيهما.
- `arduino_ide/MediLink_PN532/MediLink_PN532.ino`: نسخة Arduino IDE للوحة ESP32-S3/PN532.
- `nfc_esp32s3_pn532/platformio.ini`: بيئة بناء PN532 ومكتبة Adafruit PN532.
- `desktop/nfc_bridge.py`: أوامر `READ` و`WRITE` عبر المنفذ التسلسلي.
- `desktop/screens/core.py`: صفحة إصدار البطاقة وقراءتها وكتابتها واختيار منفذ القارئ؛ `desktop/main.py` يحدد `NFC_PORT` الافتراضي، و`desktop/api_client.py` و`desktop/widgets/common.py` يديران الطلبات ونتائجها.
- `backend/app/api/core.py` و`backend/app/services/nfc.py`: إصدار الرمز والتحقق منه وصلاحيات الموظف؛ `backend/app/schemas/requests.py` يتحقق من صيغة الرمز، و`backend/app/db/models/__init__.py` وملف Alembic ينشئان سجل البطاقة في PostgreSQL. الخادم لا يتصل بالقارئ مباشرة.
- `tests/unit/test_bridge.py` و`tests/unit/test_nfc_page.py`: اختبارات بروتوكول Serial وحالات الواجهة. اختبارات API في `tests/integration/test_core.py` و`tests/integration/test_security_validation.py`. مجلد `.pio` ناتج بناء محلي، وليس كوداً يُعدل يدوياً.

نسختا Arduino IDE الفعالتان موجودتان في `arduino_ide/MediLink_RC522/MediLink_RC522.ino` و`arduino_ide/MediLink_PN532/MediLink_PN532.ino`. أما `dist/MediLink-NFC.exe` فهو مشغّل واجهة Windows، وليس برنامجاً يُرفع إلى لوحة القارئ.

## التوصيل

استخدم 3.3V فقط، وفق التوصيل الذي نجح مع القارئ: SDA/SS=D2 (GPIO4)، SCK=D5، MOSI=D7، MISO=D6، RST=D1 (GPIO5)، مع GND مشترك. اترك IRQ غير موصول. افتح منفذ اللوحة بسرعة 115200. الواجهة تستخدم قيمة `NFC_PORT` في `.env`؛ القيمة المضبوطة حالياً على هذا الجهاز هي `COM3`، والقيمة الافتراضية في `.env.example` هي `COM6`. أغلق Arduino Serial Monitor قبل تشغيل الواجهة لأن منفذ COM لا يقبل برنامجين في الوقت نفسه.

## البناء والرفع

```powershell
.\.venv\Scripts\python.exe -m pip install platformio
.\.venv\Scripts\python.exe -m platformio run -d nfc_esp8266
.\.venv\Scripts\python.exe -m platformio run -d nfc_esp8266 -t upload
```

ملف `nfc_esp8266/platformio.ini` مضبوط على NodeMCU ESP8266 ورفع `COM3` حالياً. غيّر `upload_port` إن تغيّر منفذ اللوحة، واجعل `NFC_PORT` في `.env` يشير إلى المنفذ نفسه. البناء وحده لا يثبت أن RC522 يقرأ بطاقة. إذا ظهرت `reader_not_detected` أو `version: 0x00` أو `0xFF`، تحقق من 3.3V والأسلاك وSPI واللحام قبل تجربة بطاقة.

### ESP32-S3 مع PN532

هذا خيار قارئ ثانٍ مستقل عن RC522: يستخدم PN532 على I2C عبر SDA=GPIO8 وSCL=GPIO9، وفق الأرجل في sketch المرسل. اضبط مفتاح/محوّل PN532 على وضع I2C، ووصل 3.3V وGND المشترك. إشارات النجاح تستخدم buzzer فعالاً على GPIO14 وLED أخضر على GPIO12، والخطأ يستخدم LED أحمر على GPIO13؛ صِل مقاومة مناسبة على التوالي مع كل LED، واستخدم ترانزستوراً لقيادة الـbuzzer بدل تحميل رجل ESP32-S3 مباشرة. ارفع البرنامج من مجلد المشروع الجديد:

```powershell
.\.venv\Scripts\python.exe -m platformio run -d nfc_esp32s3_pn532
.\.venv\Scripts\python.exe -m platformio run -d nfc_esp32s3_pn532 -t upload
```

تحتاج اللوحة عبر USB الأصلي إلى تفعيل USB CDC عند الإقلاع. في Arduino IDE اختر USB CDC On Boot: Enabled وUSB Mode: Hardware CDC and JTAG من قائمة Tools، ثم أعد رفع البرنامج. بيئة PlatformIO تستخدم `esp32-s3-devkitc-1`؛ إذا كانت لوحتك ESP32-S3 ذات طراز مختلف، اضبط `board` في `platformio.ini` بحسب موديلها. واجهة MediLink تعرض منافذ COM المكتشفة في صفحة قارئ NFC؛ حدّث القائمة واختر منفذ اللوحة التي تريد استخدامها. يمكن توصيل اللوحتين معاً، لكن اختر منفذاً واحداً للعملية الحالية. لا تفتح Serial Monitor أثناء استخدام الواجهة.

### الرفع من Arduino IDE

افتح `arduino_ide/MediLink_RC522/MediLink_RC522.ino` واختر **NodeMCU 1.0 (ESP-12E Module)**، أو افتح `arduino_ide/MediLink_PN532/MediLink_PN532.ino` واختر **ESP32S3 Dev Module**. ثبّت مكتبة MFRC522 للأول وAdafruit PN532 للثاني من Library Manager، ثم اختر منفذ COM وارفع. حزمة ESP8266 تُضاف من Boards Manager برابط `https://arduino.esp8266.com/stable/package_esp8266com_index.json`. بعد رفع البرنامجين، أعد تشغيل MediLink، حدّث قائمة المنافذ واختر منفذ القارئ المراد استخدامه؛ التطبيق يشغّل قارئاً واحداً لكل عملية.

## البطاقة والرمز

يدعم البرنامج بطاقة MIFARE Classic 1K تجريبية بمفتاح القطاع 1 الافتراضي. يخزن علامة `MLN1` و32 بايت من الرمز في كتل البيانات 4–6 من القطاع 1، ولا يمس كتلة المفاتيح 7. ستُستبدل بيانات الكتل 4–6؛ استخدم بطاقة مخصصة للمشروع فقط. بطاقات Type 2 وClassic 4K وDESFire ليست ضمن مسار البرنامج الحالي.

الخادم ينشئ رمزاً عشوائياً من 64 خانة hex، ويخزن SHA-256 له فقط في PostgreSQL. إصدار أو استبدال الرمز يلغي السابق. UID لا يُقبل في API ولا يفتح ملف المريض. قراءة الملف تتطلب تسجيل دخول موظف وصلاحية الوصول للمستشفى، وتُسجّل في Audit Log. البطاقة ليست إثبات هوية، وهي قابلة للنسخ مادياً؛ استخدم بيانات تجريبية فقط.

## الاستخدام

1. سجّل الدخول بحساب استقبال، وافتح ملف مريض تجريبي، واختر منفذ اللوحة المتصلة بالقارئ، واضغط «تهيئة البطاقة تلقائياً» وأكّد استخدام البطاقة التجريبية.
2. قرّب البطاقة المخصصة للمشروع من RC522 وأبقها ثابتة. يحجز البرنامج رمزاً، يكتبه ويتحقق من قراءته، ثم يفعّله ويفتح ملف المريض. إذا فشلت الكتابة يبقى الرمز السابق فعّالاً بالخادم، ويمكن الضغط على «كتابة الرمز على بطاقة تجريبية» لإعادة المحاولة. عند الاستبدال استخدم بطاقة منفصلة عن القديمة؛ الكتابة على نفس البطاقة قد تتلف محتواها السابق عند الفشل.
3. لاحقاً اختر منفذ القارئ نفسه واضغط «قراءة مباشرة من القارئ» مع إبقاء البطاقة قريبة أو أعد تقريبها؛ يرسل Desktop أمر `READ` ثم الرمز إلى `/api/nfc/scan` ويفتح الملف إذا كانت البطاقة ما زالت فعالة والموظف مخولاً.

من ملف المريض تظهر حالة البطاقة الفعالة وتاريخ إصدارها. زر «تهيئة البطاقة تلقائياً» لا يلغي البطاقة الفعالة السابقة إلا بعد نجاح كتابة الجديدة وتفعيلها. زر «إلغاء البطاقة» يبطلها فوراً. زر «قراءة مباشرة من القارئ» لا يحتاج UID أو إدخال رمز؛ يقرأ البطاقة من المنفذ المختار ثم يفتح الملف عبر الخادم.

تُبطل الكتابة marker أولاً، ثم تكتب الرمز، ثم marker أخيراً، ثم تعيد القراءة للتحقق. إذا انقطعت الكتابة فقد تبقى البطاقة الجديدة بلا رمز صالح، لكن البطاقة القديمة تبقى فعالة. أعد كتابة الرمز المحجوز من الواجهة أو ابدأ التهيئة من جديد. بعد تفعيل رمز جديد في الخادم، يصبح القديم غير صالح حتى لو بقي على البطاقة.

## بروتوكول Serial

كلتا اللوحتين ترسلان JSON سطراً بسطر بسرعة 115200: `ready` عند البدء، و`reader_connected` أو `reader_not_detected` دورياً. للقراءة يرسل Desktop `READ` متبوعاً بسطر جديد؛ ترد اللوحة بـ`read_ready`، ثم الرمز عند قراءة بطاقة مهيأة. عند تعذر القراءة ترسل `card_not_provisioned` أو حالة خطأ أخرى. للكتابة يرسل Desktop `WRITE <64 lowercase hex>`؛ ترد اللوحة بـ`write_ready` ثم `{"ok":true,"written":true}` بعد التحقق. قد تعيد إعادة فتح المنفذ تشغيل اللوحة؛ الجسر ينتظر رسالة البدء قبل إرسال الأمر. لا يُسجل الرمز في المخرجات التشخيصية.

## التحقق الذي يحتاج جهازاً فعلياً

على هذا الجهاز، تحقق الاتصال بـRC522 على `COM6` مع `version: 0x92`. اختُبرت كتابة رمز إلى بطاقة MIFARE Classic 1K تجريبية (النوع 4) وقراءته ومطابقته، ثم أُصدر رمز للمريض التجريبي رقم 7 ونجح `/api/nfc/scan` في فتح ملفه بعد قراءة البطاقة. في مراجعة 2026-11-03 نجح بناء PlatformIO واختبارات الجسر والواجهة، ورد الجهاز بـ`reader_connected` و`0x92`؛ وصل أمر `READ` وانتهى برد `read_timeout` من اللوحة لأن بطاقة لم تُقرأ خلال المهلة. لم تُعد تجربة الكتابة الفعلية في هذه المراجعة، ولم يُختبر فصل اللوحة أثناء العملية أو بطاقة غير متوافقة أو إلغاء الرمز بعد الكتابة.
