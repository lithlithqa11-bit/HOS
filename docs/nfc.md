# NFC: المحاكاة والعتاد الحقيقي

## مبدأ الأمان

الخادم يولد `secrets.token_hex(32)`؛ أي 256 بت عشوائية. PostgreSQL يخزن SHA-256 للرمز فقط، ويعيد الأصل مرة واحدة عند الإصدار. تُلغى البطاقة القديمة عند الاستبدال ضمن نفس المعاملة. البطاقة ليست وسيلة تسجيل دخول؛ كل عملية بحث تتطلب JWT للموظف ومنحة وصول للمستشفى. UID لا يُقبل في API ولا يُستخدم لاعتماد وصول.

بطاقة Type 2 لا تمنع النسخ مادياً. النظام نموذج تعليمي ولا يعتبر الرمز إثبات هوية. لا تُخزن الأسماء أو التشخيصات أو الأدوية على البطاقة.

من ملف مريض بحساب استقبال: «إصدار / استبدال بطاقة»، ثم «قراءة NFC» في وضع المحاكاة. الرمز يُمرر عبر نفس `/api/nfc/scan` المستخدم في القراءة الحقيقية. جميع النتائج من قاعدة البيانات. يمكنك نسخ الرمز لأغراض العرض من حقل المحاكاة؛ لا يُطبع في السجل.

## البناء على Windows

ثبت CMake ومترجم Visual Studio Build Tools C++ أو MinGW-w64. مكتبة Winscard متاحة ضمن Windows SDK / MinGW.

```powershell
cmake -S nfc_cpp -B nfc_cpp/build
cmake --build nfc_cpp/build --config Release
```

مع MinGW:

```powershell
cmake -S nfc_cpp -B nfc_cpp/build -G "MinGW Makefiles"
cmake --build nfc_cpp/build
```

ضبط `.env`: `NFC_EXECUTABLE=nfc_cpp/build/nfc_reader.exe` أو `nfc_cpp/build/Release/nfc_reader.exe` عند MSVC. مشروع CMake يدعم ربط libpcsclite على Linux لكن منصة الاختبار المستهدفة Windows.

## نوع البطاقة والأوامر

PC/SC معيار الاتصال، لكنه لا يضمن دعم أوامر ذاكرة موحدة لكل بطاقة. هذا adapter يستهدف Type 2 / NTAG / MIFARE Ultralight مع ACS-compatible pseudo APDUs. لا يدعم MIFARE Classic أو DESFire أو بطاقة ISO7816 عامة تلقائياً.

يقرأ CC من الصفحة 3 ويتحقق من E1 والإصدار 1 ومساحة 48 بايت على الأقل وإتاحة الوصول. `FF B0 00 page 10` يقرأ 16 بايت، و`FF D6 00 page 04` يكتب صفحة 4 بايت. يتحقق من SW=9000 وطول الرد. يخزن marker ثابت MLN1 في الصفحة 4 و32 بايت رمزاً في الصفحات 5–12. الصيغة الخاصة بالمشروع ليست ملف NDEF عاماً.

تتطلب الكتابة `--write-token-stdin --confirm-type2` ويصل الرمز عبر stdin، مع تأكيد الواجهة أن البطاقة تجريبية مخصصة. يتم إبطال marker أولاً، ثم كتابة الرمز، ثم marker، ثم قراءة تحقق. لا تُكتب صفحات الشركة أو القفل. فشل التهيئة الفعلية لا يعيد تفعيل بطاقة قديمة؛ أعد محاولة كتابة الرمز الحالي أو استبدله في الخادم.

## بروتوكول العملية

نجاح القراءة: `{"ok":true,"token":"64 lowercase hex characters","reader":"PC/SC Type2"}`.

نجاح الكتابة: `{"ok":true,"written":true}`. الفشل: `{"ok":false,"error":"no_reader"}` أو no_card_or_reader_busy / pcsc_service_unavailable / unsupported_apdu_or_card_access_denied وغيرها. stdout يحتوي JSON واحداً فقط وexit code غير صفري عند الفشل. Python يفرض مهلة 15 ثانية ولا يستعمل shell.

## الاختبارات التي تحتاج جهازاً حقيقياً

لم يُختبر قارئ ACS ACR1552U أو بطاقة حقيقية في بيئة البناء. يلزم تنفيذ التالي وتسجيل الطراز وإصدار firmware ونوع البطاقة:

1. تثبيت driver والتأكد من ظهور القارئ في PC/SC؛ اختبار فصل القارئ وغياب البطاقة.
2. التحقق من دعم FF B0/FF D6 ونوع Type 2 قبل الكتابة. بعض قارئات PC/SC تتطلب adapter مختلفاً.
3. إصدار رمز من استقبال ثم كتابته على بطاقة تجريبية فارغة مخصصة فقط.
4. إعادة القراءة والمقارنة، ثم جلب ملف المريض من API بعد تسجيل الدخول.
5. اختبار بطاقة غير مهيأة، محمية، غير متوافقة، ورفع البطاقة أثناء القراءة والكتابة.
6. إلغاء البطاقة في النظام ثم التأكد من رفضها، واستبدالها ببطاقة جديدة.

مرجع الأوامر: [ACS ACR1552U Series Reference Manual](https://www.acs.com.hk/download-manual/13475/REF-ACR1552U-Series-1.05.pdf). الوثائق مرجع للتنفيذ وليست دليلاً على اختبار الجهاز. يجب التحقق من دليل إصدار القارئ المتاح فعلياً.
